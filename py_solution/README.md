## 二、建模方法

### 2.1 运动学

- **导弹**：匀速直线指向原点，`M(t) = M0 + 300·(-M0/|M0|)·t`
- **无人机**：等高匀速直线，`FY(t) = FY0 + v·[cosθ, sinθ, 0]·t`
- **烟幕弹平抛**（投放→起爆）：水平随无人机速度，竖直 `z - 0.5·g·Δt²`
- **云团下沉**（起爆后）：xy固定在起爆点，`z(t) = z_爆 - 2.5·(t - t_爆)`

### 2.2 遮蔽判定（核心）

从导弹视角判断真目标是否被云团挡住：
1. 导弹进入云团内部（`|M-S| < 10`）→ 遮蔽有效
2. 云团在导弹与目标之间，且真目标离散关键点**全部**落在"以导弹为顶点、导弹→云团为轴、云团半径定半顶角"的视锥内 → 遮蔽有效
3. 多弹场景支持"互补遮蔽"：某时刻每个关键点只要被**至少一朵**存活云团挡住即算有效（不要求单朵云独挡全部）

视锥判据：`sin α = 10/|M-S|`，关键点i偏离角 `cos γ_i = axis·(K_i-M)/(|axis||K_i-M|)`，若 `∀i: cos α ≤ cos γ_i` 则全部在锥内。

### 2.3 优化方法（A线）

- **问题2**：4维 PSO（θ, v, 投放, 延时）
- **问题3**：8维 PSO（θ, v, 3×投放, 3×延时），先用单弹快速预搜出热启动种子
- **问题4**：两阶段——阶段1把"3机各投1弹"拆成3个独立单机问题分别求解，阶段2以其为中心收窄边界做12维联合精修
- **问题5**：两阶段——阶段1逐机单独优化，阶段2以其为中心做40维联合微调
- 每问 PSO 收敛后再做一次 Powell 无梯度局部精修收尾

## 三、性能修复与双精度机制（2026-07）

### 3.1 之前为什么跑到问题4就崩

- `pso.py` 按 `os.cpu_count()`（本机=32）开满并行进程
- 而问题4/5每次目标函数评估峰值约 **1.7GB**（`_multi_cloud_coverage_mask` 里 `(时间步×关键点×3)` 的大数组没分块）
- 32 × 1.7GB ≈ 54GB 远超物理内存 → **OOM 崩溃**。问题3每次仅390MB，×32≈12GB勉强撑住，所以"跑完第3问就停"。

### 3.2 三项修复

1. **内存分块**（`simulation.py`）：`_multi_cloud_coverage_mask` 的大数组按时间维分块（单块≤1e7元素），单次评估峰值从1.7GB降到<400MB，语义不变。
2. **进程数按可用内存动态封顶**（`pso.py`）：不再无脑开32个。取 `min(CPU核数, config.PSO_MAX_WORKERS, 按当前空闲内存能容纳的进程数)`，并把每个worker的BLAS线程锁为1避免超额订阅。可用环境变量 `CUMCM_PSO_WORKERS=6` 手动指定。
3. **搜索档 / 定稿档双精度**（`config.py`）：
   - **搜索档**（`SEARCH_N_CIRCLE=180, SEARCH_N_LAYERS=5, SEARCH_DT=0.01`）：跑PSO用，单次评估比定稿档快约7倍、内存省约7倍
   - **定稿档**（`FINAL_N_CIRCLE=360, FINAL_N_LAYERS=10, FINAL_DT=0.005`）：PSO找到最优解后，用精细档复算一遍作为最终上报数值
   - 依据：敏感性分析表明关键点数>100即收敛，180圆周点足够引导PSO找对解，最终数值再用精细档保精度


### 问题1为什么是0

C题把投放1.5→1.2s、延时3.6→3.2s，云团在 t=4.4s 就形成（A题5.1s），比A题早0.7s。经全精度验证，导弹全程离云团中心最近 **10.73m**，只比有效半径10m多0.73m，没真正穿过云团——这是三个参数改动叠加后的真实"贴边"情况，不是bug。论文里加一句敏感性说明即可（"最近距离10.73m略大于有效半径10m，遮蔽窗口趋近于0"）。
