# 四篇论文对"有效遮蔽时间"的定义分析

## 核心问题

在多导弹场景（P4、P5）中，"总有效遮蔽时间"有三种可能的理解方式：

| 理解方式 | 含义 | 公式 |
|---------|------|------|
| **A: 全局求并 (Global UNION)** | 所有导弹的所有遮蔽区间取并集，重叠部分只算一次 | `T = |U_1 ∪ U_2 ∪ U_3|` |
| **B: 分导弹求并再求和 (Per-missile UNION + SUM)** | 每枚导弹内部遮蔽区间取并，然后三枚导弹求和 | `T = |U_1| + |U_2| + |U_3|` |
| **C: 同时遮蔽取交集 (Intersection)** | 只有三枚导弹**同时**被遮蔽的时间才算 | `T = |U_1 ∩ U_2 ∩ U_3|` |

## 逐论文详细分析

### Paper 1 (cumcm25003) — **UNION内 + SUM跨**

**P3公式 (单机三弹针对同一导弹，论文公式18)**:
```
T_block = |T1 ∪ T2 ∪ T3| 
        = |T1| + |T2| + |T3| - |T1∩T2| - |T3∩T2| - |T3∩T1| + |T1∩T2∩T3|
```
这是标准的**并集容斥公式**，同一枚导弹的3个烟幕弹遮蔽区间取**并集**。

**P5公式 (论文公式28)**:
```
max Σ_j w_j · Σ_i T_block(i, v_i, t_drop_ij, t_blast_ij)
```
其中 j = 1,2,3 为导弹索引。明确对三枚导弹**求和** (Σ_j)，且可以加权。

**代码实现** (`compute_total_cover_time_multi()`):
```python
all_intervals = []
for t_drop, t_explode in zip(t_drops, t_explodes):
    intervals = get_smoke_cover_intervals(...)
    all_intervals.extend(intervals)     # 收集所有区间
all_intervals.sort()
merged = [...]                           # 合并重叠区间 = UNION
return sum(end - start for start, end in merged)  # 求并集总长
```

✅ **结论**: 单个导弹内部取UNION，多导弹之间取SUM。即 **理解方式B**。

### Paper 2 (cumcm25028) — **UNION内 + SUM跨**

**P4结果检验**:
```
12.45s = 4.65s (FY1: [1.10, 5.75]) 
       + 4.00s (FY2: [19.15, 23.15]) 
       + 3.80s (FY3: [29.75, 33.55])
```
三架无人机的时间窗口**完全不重叠** (1.10~5.75, 19.15~23.15, 29.75~33.55)，因此此时 UNION = SUM = 12.45s。

**P5策略**: GA同时优化所有无人机-导弹对，使用 `intersection_matrix` 检查每一时刻每枚导弹的遮蔽状态，分别计算每枚导弹的遮蔽时间后**求和**。

**代码证据** (MATLAB):
```matlab
shield_time = sum(time_intervals(:, 2) - time_intervals(:, 1));  % 求并集时长
% 对多导弹场景: M1_time + M2_time + M3_time
```

✅ **结论**: 与Paper 1一致，**理解方式B**。

### Paper 3 (cumcm25043) — **P4全局UNION / P5分导弹UNION+SUM**

**P4代码** (`fitness_of_particle()`):
```python
all_ivs = []
[all_ivs.extend(tracks[u]) for u in ["FY1","FY2","FY3"]]  # 所有无人机区间
L = union_length(merge_intervals(all_ivs))                  # 全局合并取UNION
```
P4中三架无人机都针对同一枚导弹M1，因此**全局UNION = 单导弹UNION**，这里两种理解等价。

**P5代码** (`objective_sum_of_unions()`):
```python
def objective_sum_of_unions(chosen_events, dt=VERIFY_DT):
    per = per_missile_union_intervals(chosen_events, dt=dt)
    return sum(union_length(per[m]) for m in per.keys()), per
    #      ^^^                                              ^^^
    #      分导弹UNION后，跨导弹SUM                          返回 per = {M1: [...], M2: [...], M3: [...]}
```
**分导弹独立求并集**，然后**跨导弹求和**。

**输出示例**:
```
M1: 12.5s intervals=[...]
M2: 10.3s intervals=[...]
M3: 11.2s intervals=[...]
SUM = 34.000s
```

✅ **结论**: P5使用**理解方式B** (per-missile union + sum)。P4中因所有无人机针对同一导弹，union等价。

### Paper 4 (cumcm25086) — **UNION内 + SUM跨 (最明确)**

**这是4篇论文中分导弹管理最清晰的一篇。**

**代码结构**:
```matlab
% 三个独立存储，每枚导弹独立维护遮蔽区间
U_missile = {zeros(0,2), zeros(0,2), zeros(0,2)};

% 每次添加新遮蔽区间时，仅更新对应导弹
U_missile{mid_i} = union_all([U_missile{mid_i}; iv_fine_i]);

% 最终输出: 分导弹显示 + 求和
totM = [total_len(U_missile{1}), total_len(U_missile{2}), total_len(U_missile{3})];
fprintf('M1=%.3f s, M2=%.3f s, M3=%.3f s | SUM=%.3f s\n', totM(1), totM(2), totM(3), sum(totM));
```

**核心函数**:
| 函数 | 功能 |
|------|------|
| `union_all()` | 合并重叠遮蔽区间 (UNION) |
| `total_len()` | 求并集总时长 |
| `fit_union()` | 适应度函数，UNION后算时长 |
| `marginal_all_of_3()` | 对3枚导弹分别计算边际增益 |

✅ **结论**: 最明确的**理解方式B**，甚至文件名都叫 `fit_union.m`、`union_all.m`。

## 最终结论

### 🎯 四篇论文的理解方式**完全一致**

全部使用 **理解方式B: Per-missile UNION + Cross-missile SUM**，即：

1. **同一枚导弹**的多个烟幕弹遮蔽区间取**并集 (UNION)** — 重叠时间只算一次
2. **三枚导弹(M1/M2/M3)**的遮蔽时间**独立相加 (SUM)** — 即 `T_total = T_M1 + T_M2 + T_M3`

### ❌ 没有论文使用"同时遮蔽所有导弹"(Intersection)的定义

"三枚导弹必须同时被遮蔽才能计数"这种最严格的理解方式(C)在4篇论文中都没有被采用。如果采用这种方式，P5的结果会远小于现有数值（可能只有0~2秒）。

### 📊 数值差异的真正原因

既然理解方式一致，那P4/P5的数值差异来自：
1. **优化算法不同**: L-BFGS-B vs GA vs PSO vs APSO
2. **搜索精度不同**: 粒子数、迭代数、采样密度
3. **目标离散化不同**: 550点 vs 36+投影 vs 360点 vs 圆盘投影
4. **无人机-导弹分配策略不同**: Paper4使用贪心边际分配，Paper2使用GA全局分配
5. **FY3/FY5几何可达性**: 位于Y轴负半轴的无人机在120m/s速度上限下难以飞抵有效位置

### ⚠️ 当年的争议可能是

虽然这4篇论文理解一致，但2025年A题确实存在"遮蔽时间如何定义"的歧义。题目原文只说"有效遮蔽时间"，并未明确是多导弹求和还是取并还是取交。因此不排除当年有其他参赛队采用了理解方式A或C，导致数值差异巨大。
