# C题 烟幕干扰弹的投放策略 — 项目总览

## 这是什么题

本项目为烟幕干扰弹投放策略问题的 Python 求解实现与配套论文。

参数改动（详见 `C题改动报告.md`）：

| 物理量 | 题目给定值 |
|------|------------|-------------|
| 烟幕云团下沉速度 | 3.0 m/s | **2.5 m/s** |
| 无人机飞行速度范围 | 70~140 m/s | **80~120 m/s** |
| 问题1投放时间 | 1.5 s | **1.2 s** |
| 问题1起爆延时 | 3.6 s | **3.2 s** |

其余（导弹速度、目标尺寸、各初始坐标、遮蔽半径10m、有效时长20s、投放间隔≥1s）全部不变。**建模框架可直接复用A题思路，只换这几个数值。**

## py_solution 里有两条流水线（重要）

`py_solution/` 内部并存两套**互相独立**的求解代码，这是历史遗留的主要混乱来源：

| | 入口 | 方法 | 定位 |
|---|---|---|---|
| **A线（主力）** | `main.py` → `problem1~5.py` + `pso.py` | 正规 PSO 联合优化 | ✅ 以此为最终结果来源 |
| **B线（废弃）** | `final_solve.py` / `run_all_v2.py` | 随机采样猜起爆点 | ⚠️ 会系统性丢解、分数偏低，仅供参考 |

## 已知修复（2026-07）

之前 A线 跑到问题4会崩溃（CPU 100% + 爆内存）。根因是 `pso.py` 按 CPU 核数（本机32）开满并行进程，而每次问题4/5的评估峰值约 1.7GB，32×1.7GB≈54GB 远超内存 → OOM。已修复：

1. **内存分块**：仿真核心的大数组按块计算，单次评估峰值降到 <400MB。
2. **进程数按可用内存动态封顶**：不再无脑开32个，按当前空闲内存算安全进程数。
3. **搜索档/定稿档双精度**：PSO 用粗档（180关键点/dt0.01）快速搜索，最优解再用精细档（360关键点/dt0.005）复算上报，兼顾速度与精度。
4. **P5 修了一个隐藏老 bug**：阶段2 的变量顺序曾与目标函数解码顺序错位（按类型分组 vs 按机交错），导致联合优化恒为 0。修正后 P5 阶段1 还把 P4 验证好用的"三维空间采样"搜法移植过来，让 FY2~FY5 也能找到解。

修复 + 增强后的 A线 全跑实测约 **77 分钟**（P5 增强后是 B线 5.84s 的 3 倍多 → 18.40s），跑得通、结果对、数值不再有 0/垃圾参数。
